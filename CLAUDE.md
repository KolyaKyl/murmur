# Проект: новое приложение (рабочее имя Murmur)

Flutter-приложение для успокоения, сна и работы с эмоциональным состоянием.
Собирается на кодовой базе прошлого продукта **Self Screen** — код переиспользуется,
продукт делается новый.

## Концепт

Человек живёт среди шума и раздражителей. Приходит в приложение — успокаивается,
снижает тревогу, засыпает. Четыре опоры:

1. **Библиотека звуков** — природа, сон, фокус, медитация. Это **ядро продукта**, фокус смещён сюда
2. **Дыхательные практики** — список карточек + экран практики с анимацией
3. **Mood-трекер** — индекс настроения, эмоции, дневник, аналитика (уже написан, работает)
4. **Профиль** — настройки, всё из бывшего дровера

Дальше планируются: дневник записей, ежедневные inspiration quotes.

## Целевая архитектура

**Навигация**
- `MainShell` + `IndexedStack` — состояние табов и плеер живут при переключении
- 4 вложенных `Navigator` с `GlobalKey` — пуш внутри таба не прячет бар
- полный плеер и модалки — на **root**-навигаторе, поверх бара
- тап по активному табу → pop до корня + скролл наверх
- `PopScope`: назад → pop таба → таб 0 → выход

**Стеклянный бар**
- в Flutter 3.41 встроенного Liquid Glass API нет (проверено — символа `LiquidGlass` в SDK нет).
  Делаем свой, без пакетов
- `ClipRRect(radius: 30)` + `BackdropFilter(blur 24)` + заливка `surface.withValues(alpha: .55)`
  + верхний hairline `white@.35` + тень
- плавающая пилюля: 16 по бокам, 12 над `SafeArea`, высота 62
- **критично:** `Scaffold(extendBody: true)` на каждом табе + нижний паддинг ~96 в каждом
  скролле, иначе под баром пусто и стекло выглядит мутным пластиком
- мини-плеер докуется над баром, живёт в `MainShell`

**Табы**
1. Home — moodindex (существующий код) + «Продолжить слушать» + «Практика дня».
   Mood Analysis — кнопкой на карточке индекса
2. Звуки — категории, сетка, тап играет сразу и поднимает мини-плеер
3. Дыхание — карточки практик, экран с анимированным кольцом
4. Профиль — перенос дровера, редактирование профиля отдельным экраном

**Firestore (новое)**

Каталог заполняется **вручную через консоль**, поэтому схема плоская:
```
sounds/{id}   title, subtitle, category, audioUrl, duration, color, premium, order
soundCategories/{id}, breathingPractices/{id}
users/{uid}/favorites/{soundId}, users/{uid}/MoodRecords/*
```

**Зависимости к добавлению:** `just_audio`, `just_audio_background`, `audio_session`,
`shared_preferences`. Позже — `purchases_flutter`.

## Долги кодовой базы — чинить попутно

- **`GlobalKey<WellnessCardState>` ходит по всему дереву** — прокидывается в `FirebaseService`,
  в дровер, в экран анализа, только чтобы дёрнуть перерисовку. Для этого в проекте уже стоит
  Riverpod. С глобальным плеером такой подход развалится. Вынести в провайдеры
- **Ошибки глотаются** — `catch (e) { return []; }` по всему `FirebaseService`.
  Нет сети → пустой экран без объяснений
- **Типографики нет вообще** — `TextTheme` не определён ни разу, `google_fonts` в зависимостях
  и не используется ни в одном файле
- **101 хардкоженный `Colors.*`** мимо темы (32 × grey, 14 × red, 7 × black) — в тёмной теме не переворачиваются
- **Радиусы вразнобой** — 47 × `circular(12)`, 25 × `circular(16)`, плюс 8/10/20/4/2
- **Нет локального хранилища** — тема живёт только в Firestore, на холодном старте приложение
  светит белым и потом перекрашивается

## Технические заметки

- **Секреты не в репозитории:** `android/local.properties` (содержит пароли keystore) и
  `android/app/release/my-stuff.jks` лежат на диске, закрыты в `.gitignore`.
  При клонировании на другую машину их надо принести руками, иначе не соберётся
- **Firebase-конфиги пока старые.** `google-services.json`, `GoogleService-Info.plist`,
  `firebase_options.dart` смотрят на проект `self-screen-1de5f`.
  До Фазы 1 приложение пишет в боевую базу старого продукта — на выпиливании не страшно,
  но **до работы над звуками новый проект обязателен**
- `web/`, `macos/`, `windows/`, `linux/` не в репозитории — приложение только iOS + Android
- **`minSdkVersion` держим явной цифрой `23`**, не `flutter.minSdkVersion`. Flutter при сборке
  пытается подставить своё значение — откатывать. Явная цифра нужна, чтобы минимальная версия
  Android не плавала при обновлениях Flutter; Firebase требует минимум 23
- При заведении нового Firebase два решения необратимы: **регион Firestore** и то, что
  Cloud Storage у новых проектов требует Blaze
